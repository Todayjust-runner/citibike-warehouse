## 发现并修正：已验证输入仍可追加原始行

问题 B3-01：B2-1.0 的 ODS 触发器仅拒绝 UPDATE/DELETE。源成员被 VALIDATED/PUBLISHED 运行引用后，仍可 INSERT 新记录，使已验证的原始读取计数和去向守恒失效。它影响审计快照稳定性，不改变六指标定义。

先加 3 个真实 SQL 回滚用例：VALIDATED 源追加应拒绝、PUBLISHED 源追加应拒绝、另一新源应仍允许插入。旧版 50 用例中前两个失败，actual_error=0，明确观察到不应成功的插入；新源正例通过。测试集故意失败时由 sqlcmd 抛 51201，CLI 返回 sql_error/退出 2；从标记结果中提取两项失败，而非把传输错误当功能失败。

修正为既有 `ods.TR_trip_raw_immutable` 监听 INSERT/UPDATE/DELETE，保留改删保护，并检查新增行的来源是否被已验证/发布运行引用，使用运行锁与冻结机制协调；命中抛 51042。不增加表/列/索引/模块，不实现 ETL。源码与编译清单、版本、DDL SHA 一并更新为 B2-1.1。

补丁前再次比较完整旧目录/版本/指纹，确认非种子表为空。新版默认 deploy 对旧库按预期返回 schema_drift，没有自动修复。随后仅在测试库一个事务内更改该触发器和 schema/manifest 两个扩展属性；无重建、清空或业务库操作。旧指纹与新指纹、前后计数及 RED 结果记录在[执行摘要](../evidence/b3-execution-summary.json)。遇其他 B2-1.0 库时需单独审阅迁移，不能只修改版本标记。
