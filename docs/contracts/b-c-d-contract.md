## 共同时间与事实契约

- 主窗口 `[2024-07-01T00:00:00, 2024-10-01T00:00:00)`，也支持同一规则下参数化窗口；源时间无偏移，不自动转为北京时间。运行审计时间另记并说明时区。
- 原始层一行是一条源 CSV 记录，保留 13 列原值、文件/成员身份和行定位；明细层一行是通过规则的唯一 `ride_id`。事实需能回溯保留/重复/冲突的源记录集合。
- 起终时间至少毫秒，`duration_us` 为整数微秒；准入 `[60,000,000, 86,400,000,000]`，两端包含。无效 ID/时间、冲突及超范围记录隔离并统计；未知站点或无效坐标不能据此排除有效骑行。
- 原始输入至少覆盖 A 声明的 6-10 月；是否足够、每包包含哪些事件时间由实际核验决定。不能先把 started_at 限在 Q3 再算归还，也不能把文件名当分区事实。
- 车型和会员类型的未知值要保留；字典和标签标准化需说明原值到规范值映射。起终站点为同一维度的不同角色；日期/时间亦然。
- 站点缺失用专用未知成员，具体代理键由 B1 冻结；不得碰撞真实站点 ID。名字/坐标变化策略必须可审查，不凭静态快照虚构历史版本。

## 指标接口最低要求

| 指标 | 时间角色与运算 | NULL/过滤要求 |
|---|---|---|
| M01 ride_count | 出发窗口内的有效唯一骑行数 | 允许日期与车型筛选；未知站点仍计 |
| M02 avg_duration_minutes | 同 M01 集合的总微秒 / 60000000.0 / 总次数 | 零次数返回 NULL；展示 2 位小数；不能平均月均值 |
| M03 member_share | 同 M01 窗口的 member / (member+casual) | 不接受预先仅 member 的构成卡筛选；未知类型不入分母，另报覆盖率 |
| M04 departures | 起点站 + started_at 事件桶计数 | 未知站点进入核算总量；合计等于同筛选 M01 |
| M05 arrivals | 终点站 + ended_at 事件桶计数 | 可包含窗口前出发；不要求等于 M01 |
| M06 net_outflow | 同站/同事件桶的 M04-M05 | 两侧分别聚合再全外连接；只在已确认覆盖内缺事件时补 0 |

所有比较需对齐窗口、车型、口径版本和批次。站点筛选分别作用于事件两侧，不要求一条骑行两端都等于所选站。星期计算采用固定规则，并注明周序，不将星期一至五等同全部工作日。无数据覆盖必须单独标注，不能显示成真实 0。

## C → D 结果结构（沿用 A 的最低字段）

| 结果 | 一行粒度 | 必要字段 |
|---|---|---|
| 骑行总览 | 当前出发窗口及车型集合 | ride_count, duration_us, avg_duration_minutes, member_count, known_member_type_count, member_share |
| 时段趋势 | 一个出发月/日/小时桶及分组 | time_bucket, ride_count, duration_us；分组字段显式返回 |
| 站点借还 | 一个事件站点 × 事件时间桶 | station_id, station_name, departures, arrivals, net_outflow, unknown_station_flag |
| 类型比较 | 一种会员骑行类型 × 车型 | member_casual, rideable_type, ride_count, duration_us, avg_duration_minutes |
| 公共元信息 | 一次查询/结果集合 | source_hashes, filter_start, filter_end_exclusive, bike_filter, time_role, rule_version, run_id |

此外须提供会员类型可识别覆盖率、未知起点/终点事件数、覆盖状态与完整范围说明；可在结果或公共元信息中返回，B1/C/D 冻结位置。两侧站点结果的 `time_role` 明确标为分别使用出发/归还，不能误标成单一出发时间。

v1.0 冻结时为每个字段写类型、NULL、单位、排序、过滤行为、边界与覆盖语义；需要 JSON 时，bigint 微秒和大计数应采用约定的十进制字符串或精确解析策略，避免前端 Number 精度损失。此处未承诺 REST、SQL 视图、SSAS 或网页框架。

## B → C 建模交付

1. 概念信息包/业务关系、Q1-Q3 与六指标覆盖矩阵。
2. 逻辑星型图、逐表粒度、业务/代理键、起终角色、未知成员、历史变化策略、源字段映射和可加性。
3. 物理字典与 SQL2019 DDL：表名、类型/长度/精度、NULL、PK/FK/UNIQUE/CHECK、索引、部署顺序和安全重跑。
4. 原始/异常/血缘及批次结构；互斥排除原因和源行守恒公式；仅保留一条事实时可回溯整个重复组。
5. 空库建表、元数据与约束负例的真实执行证据；明确合成夹具与真实业务验证的边界。

B 约定层职责，C 实现原始导入、明细清洗、维度装载、DWS/ADS 加工与对账，D 完成查询接入、图表及录屏。不得把这些工作借“交接示例”扩展为本阶段完整实现。

## 后续共同验收门槛

- 输入快照：ZIP 与所有 CSV 哈希对应，字段/记录数/时间覆盖复查。
- 结构：事实唯一、维度唯一关联、未知成员、字段精度和约束，连接前后计数/时长不放大。
- 边界：60 秒与 24 小时、窗首/窗尾、跨月进入/流出、空集合、未知类型/站点、坐标缺失。
- 守恒：每条源行落入保留代表行、完全重复、冲突或其他互斥排除主原因；允许附属原因多标签，但主原因不得重复计数。
- 数值：同口径明细/汇总/展示一致，先比较精确次数及总微秒，再比较舍入展示值；A 声明值需先复现方可升级为已确认基准。
- 重跑：同输入、规则与代码版本二次运行不重复累加，保存日志和差异；B 建表重跑与 C ETL 重跑分别验收。
