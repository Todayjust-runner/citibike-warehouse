# B → C：装载与加工契约

业务目标和指标以[需求说明](../requirements.md)为准；全部字段/键见[物理字典](../design/physical-data-dictionary.md)。模型1.0、物理B2-1.1，SQL Server 2019/150。

## 输入

[data/raw](../../data/raw/README.md)已包含202406—202410五个固定ZIP。每包有1个真正骑行CSV，Mac附属文件不导入；表头13列，空字段保留空字符串，CSV记录号从表头1开始计数。

[data/derived](../../data/derived/README.md)提供Q3月度、逐站和跨期对照。五包原始563874行，分析规则保留563668、排除206；当前输入无需等待A原附件即可使用。

## 装载顺序

| 顺序 | 表 | 要做什么 |
|---|---|---|
| 1 | meta.source_member、load_run、run_source | 登记文件/成员和本次run_id、输入/代码版本，开始运行 |
| 2 | ods.trip_raw | 保留所有13列原文、源成员和CSV记录号 |
| 3 | dim.date/hour、bike_type/member_type、station | 补齐两端日期与类型；站点按run构建，未知成员为0 |
| 4 | dwd.fact_trip | 每run一条有效唯一ride_id，含起止时间/角色键/微秒及代表源行 |
| 5 | meta.row_disposition、coverage、两个dws表 | 每源行一个去向；记录时间覆盖；由事实生成小时汇总 |
| 6 | meta.load_run | 对账后VALIDATED，再调用usp_publish_run发布 |

源行、事实等IDENTITY由服务器生成；五个持久化计算身份列不手工写入。站点键由C在运行内分配，日期/小时键按定义赋值。站点观察来源先指ODS，接受代表关联在整批完成时核对。

## 关键规则

- 原始层不去重、不裁Q3。非空ID/标签保留原文，以完整UTF-16LE字节作精确身份。
- 同ID比较13字段原文本：完全相同留一条，冲突整组排除。有效重复行都能追溯代表事实，排除行有互斥主原因。
- 时长保存整数微秒，60秒与24小时都包含。缺站点映射0，缺坐标只影响地图；车型/会员未知标签单列。
- 站点为每run的源观察快照：名称、坐标分别选最近接受观察，按固定源序处理并列，不建虚构SCD2。
- 所有事实/汇总查询限定一个已发布run_id。M01—M04按出发、M05按归还，M06两侧先聚合后合并。
- 次数用COUNT_BIG，总微秒汇总用decimal(38,0)；均值/比例由当前范围重算。小时不完整的窗口回事实精确筛选。

完整转换和主原因顺序见[源映射](../design/source-to-target.md)。当前数据已确认适配字段长度和精度；C仍需按实际原文装载，避免客户端截断/舍入。

## 发布前验收

源行数=接受代表+完全重复+排除，事实数=接受代表；维度关联后次数/微秒不放大，两张DWS与事实一致。同输入重跑不累加，六指标与源对照一致。通过后发布，失败运行保留诊断，不替换上次发布结果。

结果字段按[C→D契约](c-to-d-query-contract.md)实现，具体清单见[联合验收](../handoff/acceptance-checklist.md)。
