# 需求说明

## 1. 项目要解决什么问题

利用Citi Bike历史骑行数据，建立离线数仓，回答三个问题：

| 问题 | 希望看到的结果 |
|---|---|
| 什么时候骑行最多、骑多久？ | 月/日/小时趋势、星期×小时热力图、平均时长 |
| 哪些站点借出多、归还多？ | 站点借还量、净流出排名与趋势；有坐标时可画参考点 |
| 会员与临时用户、不同车型有何差异？ | 骑行次数、平均时长和会员骑行占比 |

分析对象是骑行记录。数据没有用户身份、库存和调度信息，因此不计算人数、留存或实时缺车率。

## 2. 数据和分析范围

- 来源：官方JC分区的2024年6—10月五个月包，已经放入[data目录](../data/README.md)。JC文件不是完整纽约网络。
- 默认窗口：`2024-07-01 <= 事件时间 < 2024-10-01`。6月、10月用于核对跨期骑行，不能只读7—9月文件。
- 时间按源记录使用，不换时区；每条有效骑行保存精确整数微秒时长。
- 五包共563874条源记录，按本项目规则保留563668条。事实表加载全部有效输入，季度范围在查询时选择。

## 3. 六项指标

下表的数值已在固定公开快照上独立算出，供C加载数仓后对照。

| 指标 | 怎么算 | 默认Q3结果 |
|---|---|---:|
| M01 骑行次数 | 按出发时间筛选，计算有效唯一骑行数 | 334332次 |
| M02 平均骑行时长 | 同一集合总微秒 ÷ 60000000 ÷ 次数 | 10.82分钟 |
| M03 会员骑行占比 | member次数 ÷ (member次数+casual次数) | 72.66% |
| M04 站点借出次数 | 按出发时间和起点站分别计数 | 含未知站点共334332次 |
| M05 站点归还次数 | 按归还时间和终点站分别计数 | 含未知站点共334331次 |
| M06 站点净流出 | 同站点、同事件时间范围的借出减归还 | 全站合计1次 |

M02的精确总时长为216990044333000微秒；M03的分子/分母为242927/334332。均值和占比汇总时用总分子、总分母重算，分母为0返回NULL。会员类型未知的记录不进占比分母，另显示识别覆盖率。

归还量要包含窗口前出发、窗口内归还的骑行，不能先筛出发集合再算归还。两侧分别聚合后合并；净流出可以不为0。本快照跨期进入10次、流出11次，差值正好为1。

## 4. 加工规则

1. 原始层保留13个字段原文和CSV记录位置，不提前裁季度或去重。
2. 分析骑行要求ride_id非空、起止时间可解析、`60秒 <= 时长 <= 24小时`。
3. 同ID且13字段内容完全相同的记录留一条；同ID内容冲突时整组排除。保留每条源记录的处理去向。
4. 日期、小时、站点分别有出发/归还两个角色。缺站点用未知成员，缺坐标不删除有效骑行。
5. 车型和会员类型保留原标签；未识别标签单列。站点名称/参考坐标按本次输入的确定性观察规则选取。

字段、键和具体装载规则见[设计入口](design/README.md)及[B→C契约](contracts/b-to-c-model-contract.md)。

## 6. 怎么验收

- 数据读全：源记录数等于保留代表、完全重复、排除三类之和；有效事实数等于保留代表数。
- 模型正确：同一运行ride_id唯一，关联维度后次数和总时长不增加，未知站点保留。
- 口径正确：六指标与源核算对齐，特别检查跨期、60秒/24小时、未知类型及空分母。
- 结果一致：同输入重跑不累加，查询和页面在相同运行/筛选下相等；覆盖不足不显示成真实0。
