## B1 文件与执行顺序

1. 读取现有需求、决定、缺口和 A p3、5-7；复核 Kimball 四步法的业务过程、粒度、维度与事实。输出 `docs/design/conceptual-design.md`。
2. 固定一个骑行事实及两套时间/站点角色，写 `logical-design.md` 和总线矩阵；编辑图源放 `diagrams/`。
3. 在 `logical-model.json` 声明逻辑字段、主外键与基数；`data-dictionary.md` 展示字段字典；`source-to-target.md` 覆盖 13 列及元数据、血缘和排除守恒。
4. 在 `metric-model-mapping.md` 逐项推演 M01-M06；写 B→C 与 C→D 契约，固定覆盖、NULL、未知、筛选及重算语义。
5. 静态复核字典/图/映射/契约一致，记录 `docs/evidence/b1-design-review.md`；该检查不运行 DDL，也不证明真实业务基准。
6. 更新决定、`docs/planning/STATUS.md` 和根目录导航，交接 B2；检查 Git 内容后提交并同步既有私有仓库。

## 与原建议目录的衔接

沿用已存在目录，不另外复制一套结构：`inputs/` 管来源清单，`docs/review/` 管 A 审查，`docs/decisions/` 管决定，`docs/handoff/` 管交接，`sql/validation/` 对应原方案的 checks，`etl/` 和 `dashboard/` 分别供 C/D 接续。本次新增 `docs/planning/` 与 `diagrams/`。

`docs/planning/STATUS.md` 是唯一详细阶段状态；根目录 STATUS 只保留导航和摘要。课程 PDF/书籍不复制到 docs/inputs；无需为迎合示意目录移动现有文件。`.env.example`、物理执行脚本、报告正文和图导出分别在 B2/B3 随实际内容交付。
