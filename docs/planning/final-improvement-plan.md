# 面向期末的改进方向

当前已完成固定JC五包上的需求整理、三级设计、SQL2019建表、ETL与查询验证。这证明核心数据链路可用，尚未达到完整的期末项目标准。中期展示侧重设计和阶段成果，后续重点如下，不预设时间表。

## 1. 把指标变成完整分析

围绕时段、站点借还、会员/车型三个主题，分别形成“提出问题—选择维度—比较结果—解释现象”的分析过程。

- 时间：比较月、日、小时和工作日/周末，支持上卷、下钻与切片。
- 站点：比较借还量、净流出和排名变化，保留跨期与未知站点的正确口径。
- 类型：比较会员/临时用户、不同车型的次数、时长与占比；说明哪些结论仅是数据现象。

**期末目标：** 每个主题有可复查的图表、口径和解释，而不只是展示若干KPI。

## 2. 完成可操作的展示

D接入当前已发布查询，提供统一的日期、车型和站点筛选，以及趋势、热力图、站点排名和类型对比。时间粒度、筛选条件和运行版本在各视图间保持一致。

页面需能解释数据来源、单位和空值；参考坐标用于站点展示。展示交互完成后，用同一筛选核对页面与查询结果，并录制关键功能。

**期末目标：** 观众能操作系统完成一个分析问题，页面显示与数仓结果一致。

## 3. 提高工程完整性与扩展能力

| 目前局限 | 后续改进 |
|---|---|
| 固定五包、Q3窗口和部分预期值写在脚本中 | 将输入清单、分析窗口和对账配置分离，先保持现有结果兼容 |
| 多条命令串行操作，失败后需人工定位 | 增加统一运行入口、阶段状态和恢复方式，发布前保持旧结果可用 |
| 已有DWS，查询主要读取事实层 | 对适合的完整时间桶使用汇总；部分小时等场景回到事实层，验证两种路径结果一致 |
| 目前可复现样本较固定 | 研究按月追加、日期维度扩展和字段版本适配，再决定是否扩充月份 |
| 建表夹具与真实数据测试需要分开执行 | 整理测试环境与入口，形成清晰的回归、全链路和页面对账检查 |

**期末目标：** 在新机器上按文档复现；新增输入和失败重跑有明确处理方式。

## 4. 用实测结果决定性能优化

对真实查询与ETL记录行数、耗时、资源占用和执行计划。在同一输入、环境与口径下比较优化前后，再决定索引、批量写入、连接复用、流式处理或聚合路径的调整。

如增加SSAS/MDX，应服务于明确的多维操作，并与关系型结果对账；它是可评估的拓展，不是课程文件明确指定的必选技术。

**期末目标：** 说明优化解决了什么问题，并提供可复查的测量，不把A文档中的基准当成本机结果。

## 5. 整理课程交付与演示

按课程模板补齐背景、需求、三级设计、实现、多维分析和结语；使报告、代码、PPT和录屏对应同一版本。补充真实成员分工，安排各部分讲述衔接。

**期末目标：** 材料完整，关键功能可演示；能说明设计选择、数据处理难点、分析结论及局限。

## 拓展方向

在核心分析和展示稳定后，可评估更长时间范围、季节比较或额外公共数据。扩展前先确认来源、字段与分析价值，再决定是否改模型，避免只为增加技术名词而扩大范围。
